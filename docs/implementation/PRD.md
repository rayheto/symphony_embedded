# 产品需求 PRD

## 目标

在 Symphony 原有的 Issue 驱动自主执行方式上，让嵌入式工程师理解项目结构、审阅问题解决与证据、在适当时点改变方向，并通过实际案例积累经验。常规 subagent handoff 自动流转，人类无需阅读全部 Agent 活动。

主要用户：管理一个嵌入式项目及若干设备的工程师。首发部署为单个受信任工程团队使用的一套 Symphony 实例，首先支持 Linux x86_64，Linux arm64 在发布验证中补齐。已有其它平台运行能力不得因新增工作台而回归；本版不宣称它们的设备适配已验证。

## 完整首版范围

| 编号 | 用户能力 | 交付边界 |
|---|---|---|
| R01 | 完整继承原 Symphony 执行 | 原 core gates 不回归；原 runtime API 字段兼容 |
| R02 | Issues 看板/列表 | 真实读取所有配置的展示状态；筛选、创建、详情、操作与状态回执 |
| R03 | 问题调查 | 症状、假设、实验、失败尝试、下一步、关联源码/证据可在执行中更新 |
| R04 | 可追溯证据 | 原始材料、版本、设备会话、验证条件、缺口、过期状态可查看 |
| R05 | 人类审阅与方向调整 | 意见、补证据、候选选择、采用方案、暂停与恢复；有实际生效回执 |
| R06 | 具体项目架构 | Archify 生成具体源码架构、计划结构与 Before/Delta/After，附来源及检验回执 |
| R07 | 设备与真实观测 | 设备登记、串口实时采集/导出、只暂停滚动、连接故障及资源占用可见 |
| R08 | 多模态与故障材料 | 图像源连接/帧保存、历史故障记录、原始 dump 保存；匹配符号后解码 |
| R09 | L0–L4 领域规则 | 语言/OS 中立 profile；真实项目技术绑定、跨层文件所有权、验收路径 |
| R10 | 统一美术与可访问性 | 严格落实Soft Glass v1.0四页+同风格架构宿主页，键盘可操作与文字可复制 |
| R11 | 异常与恢复 | UI/索引故障不改变 core；暂停跨重启有效、证据不随 workspace 清理 |
| R12 | 可安装可运行交付 | 干净环境启动、原 core gate、Demo/PTY/浏览器与真实设备/Agent 验证、文档 |

## 关键场景

J1 日常工作：打开 Issues → 查看 Todo/运行中 → 创建一个可执行 Issue → Agent 自主执行 → 在 Issue 内查看变化和验证 → 按工作流进入 Review/Done。
J2 调查学习：从 Issue 进入 ProblemCase → 比较被支持/被否定的假设 → 打开原始证据 → 阅读方案取舍及限制 → 添加意见或请求补充实验。
J3 掌控方向：在 Review 中选择候选 → 审阅影响范围 → 采用具体修订 → tracker workpad/计划引用更新 → 按配置恢复执行 → 看到新执行实际使用的计划版本。
J4 架构探索：选择项目与真实修订 → 生成/查看 Archify 产物 → 从来源定位实现 → 比较两个快照 → 跳转关联 Issue 或证据。
J5 真机：选设备 → 确认固件和采集会话 → 查看串口/图像/dump → 保存证据 → 关联某个验证结论。

## 非目标与约束

不新建通用 workflow engine、分布式调度器、图形排版引擎、全新任务 tracker 或多租户管理平台。首发真实写操作适配 Linear；保留原 GitHub/Jira/Asana/GitLab core adapters，工作台对它们的编辑能力按 capability 展示，不伪装成已经支持。不得把 GitHub closed 当暂停。
本版交付包括一个实际目标板卡的完整真实验证；不承诺所有芯片通用 dump 解码、不新开发用户的产品固件功能。设备操作范围先覆盖采集和经登记的诊断/复位/烧录工具；超出验证范围的工具必须显示 unsupported。

## 质量目标

正常视口 1440×900 四列八张样例卡首屏完整，不缩小字号；1280/1920 宽可操作，窄屏允许正常滚动或切列表。
本地基准 4 vCPU/8GB、100 个 Issue、100 节点分图、10k 日志行，缓存快照视图 p95 打开 ≤2s；原始日志到界面 p95 ≤1s（采集接收后计，不含设备传输），记录环境和样本数。使用有界缓冲/分页；不得为快而隐藏丢失日志。
体验验收：工程师能在 30s 内指出当前目标和主要阻塞；2 次导航内打开相关原始证据入口；3min 内解释一个案例的主要取舍。这些是测试目标，报告实际结果而非虚称已达到。

## 完成定义

R01–R12 均有实现、测试与对应证据；新环境能启动；真实 Issue→Agent→设备→证据→人类决定→继续执行链已演练；没有把模拟测试标为真机通过；视觉对照通过；已知限制有明确范围。仅有静态页面或 Demo 不构成完整交付。
