# Symphony 四界面设计提示词

## 使用方法
以下提示词可直接交给 UI 设计或前端生成工具。预览图用于表达视觉方向，具体文字、状态、字段与交互以本提示词和原始业务数据为准。图片生成可能出现文字误差，不能将图中文字作为业务数据来源。

## 主提示词
为 Symphony / Embedded Lab 设计统一的现代 Web 工程工作台，包含四个完整桌面页面：Issues 看板、调查与证据、设备与串口、方案审阅。只调整 UI 呈现，保留现有信息、操作入口、证据限制和业务含义。

### 画布与视觉系统
- 每页以 1440 × 900 CSS 像素的正常桌面视口独立设计。正文 14px，辅助信息 13px，模块标题 16–18px，页面标题 22px，日志使用 13px 等宽字体；不得为了总览拼图缩小页面内部字号。
- 中文字体 PingFang SC、Microsoft YaHei、Noto Sans SC；英文 Inter、系统无衬线；日志 ui-monospace。禁止宋体、衬线英文字体、书法字体。
- 风格安静、轻量、精细。背景 #FAFAFA，内容面板 #FFFFFF，边框 #E9EAEC，主文字 #30343B，辅助文字 #747980。圆角 6–8px，卡片只有极浅阴影。
- 外边距 24px，模块间距 16–20px，面板内边距 16–20px。通过对齐、留白、字重区分层次，避免重复套卡片和粗重分隔线。
- 控件高度 30–34px，选中导航使用浅中性灰背景。链接采用深灰文字加箭头；彩色主要用于小型状态图标与必要提醒。不得使用大面积蓝色选中行、鲜蓝大按钮、大胶囊筛选栏或装饰渐变。
- 状态：待办灰色空心圆，进行中柔和黄色进度圆，待审阅珊瑚色图标，已完成淡紫色勾选图标。在线/成功绿色，证据限制琥珀色；颜色必须配文字或不同形状。
- 顶部导航统一两行：第一行 Symphony / Embedded Lab，右侧链接、更多、H 头像；第二行 Issues、项目架构、设备、审阅记录。取消原左侧大导航。工作区切换、设置入口继续可达，可纳入工作区与头像菜单。
- 各页面在正常视口下自然排版。必要时允许内容区滚动，不通过压缩字号隐藏信息。

### 页面 1：Issues 看板
顶部选中 Issues。工具栏右侧：筛选、显示、新建 Issue；显示菜单保留列表/看板切换入口。
主体为一个全宽看板，四列同时可见：待办 3、进行中 3、待审阅 1、已完成 1。当前八张卡片必须在正常桌面首屏同时可见。列头包含状态图标、数量、更多和添加按钮。

### 页面 2：调查与证据
顶部选中 Issues。面包屑 Issues / EMB-42。标题“修复显示画面偶发撕裂”；元信息“进行中 / Driver Agent / L2 驱动”；右侧“打开 Issue”和更多。
描述：“连续切换画面时出现局部撕裂，需要核对传输与缓冲区复用时序。”
页签：概览、活动、调查与证据、变更，选中调查与证据。
主体左侧约 60%，右侧约 40%。

左侧依次展示：
1. 当前判断，标签“假设 · 尚未证实”，正文“缓冲区可能在传输结束前被复用。”
2. 调查过程时间线：10:12 复现画面撕裂，说明“连续切换画面时观察到异常。”；10:24 调整刷新频率，说明“现象仍存在，未支持刷新频率假设。”；10:36 对齐传输与复用事件，说明“正在核对事件含义与缓冲区归属。”，关联“E-017 串口片段”。最新调查节点为 10:36。
3. 下一步：“增加完成事件标记，验证释放时机。”；要求补充证据、查看关联架构；意见输入框“添加意见或调整约束…”及发送按钮。

右侧为证据 E-017，关闭按钮；日志、图像、信息页签。元信息 Board-01 · demo-build · boot-07。日志带行号，第三行浅琥珀色高亮：
```text

10:36:01.451  dma_submit buf=02
10:36:01.460  buffer_reuse buf=01
10:36:01.472  dma_done buf=01
10:36:01.475  dma_submit buf=00
```
保留“示例片段”“事件含义与顺序仍需核验”“展开上下文”“查看原始记录”。验证范围：“仅有日志片段，尚未完成真机复测。”；人类审阅：“未审阅”。这些限制持续可见，不得表达为根因已确认。

### 页面 3：设备与串口
顶部选中设备。标题“设备”，摘要“2 台设备 · 1 台在线 · 1 台离线”；刷新、添加设备。
轻量设备表格，无竖向网格线：
- Board-01 / 开发板 · rev A / 在线 / demo-build-12 / Driver Agent · EMB-42。
- Board-02 / 备用开发板 / 离线 / 未知 / 无。
选中 Board-01 使用极浅中性灰背景。详情标题 Board-01，右侧采集会话 boot-07；页签概览、串口、图像、故障记录，选中串口。
左侧约 65% 为串口与观测；右侧约 35% 为设备属性。
串口工具栏：串口采集中、115200 · 8N1、暂停滚动、导出日志。日志保持等宽、行号、原始内容，第五行高亮：
```text
10:36:01.102  boot_id=boot-07
10:36:01.210  panel_init ok
10:36:01.448  dma_submit buf=01
10:36:01.451  dma_submit buf=02
10:36:01.460  buffer_reuse buf=01
10:36:01.472  dma_done buf=01
10:36:01.510  display_frame 128
```
日志提醒：“事件顺序与含义待核验，不代表已确认根因。”；最近接收 2 秒前；打开完整记录。
其他观测两行：图像 / 尚未连接图像源 / 连接图像源；故障记录 / 本次会话暂无故障记录 / 查看历史。
右侧设备信息：硬件版本 rev A、当前固件 demo-build-12、启动会话 boot-07、观测状态采集中。当前占用 Driver Agent，关联 EMB-42 修复画面撕裂，说明“控制操作独占，日志可共享查看。”
验证范围：“真机复测未完成”“在线仅表示连接可用。”；查看构建记录、设备操作菜单。不得将在线连接等同于验证通过。

### 页面 4：方案审阅
顶部选中审阅记录。面包屑 Issues / EMB-40。标题“确认显示缓冲策略”，状态“待审阅”；审阅人贺磊；说明“审阅取舍与依据，再决定后续执行方向。”；保留更多入口。
页签方案审阅、活动记录，选中方案审阅。主体左侧约 64%，右侧约 36%。
左侧：
1. 方案对比：两个等宽轻卡片，细箭头连接。当前 r12：单缓冲 / 提交后复用；拟议 r13：单缓冲 / 完成后释放。使用小型线性层叠图标。说明“拟议方案 A 保持单缓冲，调整生命周期。”
2. 我的约束：可编辑字段“优先保证稳定性，新增内存占用需说明”，保留铅笔入口。
3. 方案取舍：A 延后释放 / 保持单缓冲，调整释放时机 / Agent 建议，默认选中；B 双缓冲 / 隔离读写，增加内存占用，未选中。使用轻量单选行，不以大色块装饰。
4. 琥珀色提示“方案 A 仍需真机验证。”
5. 依据：DISP-12 调查过程、E-017 串口片段；说明“现有证据尚不足以确认根因。”

右侧：
1. 影响范围：显示驱动 / 需调整；显示服务 / 需重验；录音链路 / 可继续。前两项琥珀色，后一项绿色，均配文字。
2. 执行回执三步：暂停请求 / 已记录请求并通知相关负责人 / 已记录；相关任务 / 已停止相关任务执行 / 已停止；新方案 / 待采用后按计划执行 / 尚未执行。
3. 说明“停止回执已确认，其他任务继续运行。”
4. 深灰色主按钮“采用方案 A”；次按钮“要求补充证据”；文字操作“继续讨论”。说明“采用后按工作流更新计划与任务。”
底栏“3 个任务运行中 · 1 个任务已暂停”。选中 A 仅表示候选选择，不代表已采用；采用方案不代表已执行或已验证；必须保留三种回执状态的区别。

### 交付与验收要求
- 四个页面分别是完整正常桌面视口，不是小卡片截图。四页总览采用 2×2 等尺寸拼排；建议总览导出 2880×1800 或更高原生分辨率，拼排时不改变页面内部字号与布局。
- 不删字段、提醒、日志、任务卡片或原有操作，不虚构额外页面与业务结论。
- 图片只表达视觉方案；实现时文字可选择、日志可复制、控件可键盘操作，状态不只依赖颜色。核对原始业务数据后再连接真实动作。
- 检查四页导航、字体、间距、按钮、图标与状态用色是否统一，检查全部内容无裁切与重叠。
